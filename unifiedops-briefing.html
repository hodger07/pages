UnifiedOps — Team Briefing

From the Principal  ·  May 2026

The 21 by 10 is the framework. This is the software that makes it impossible to ignore.

Two weeks ago I published the framework. Five functions. Twenty-one metrics. Cleared by 10 AM, every day. We agreed it's the standard. We agreed quiet reds — calling something green that isn't — are grounds for removal. We agreed honest reds make the business better.

A framework that lives in a document changes nothing. It has to live in the workflow, in real time, with no place to hide. That's what we're building.

Service Titan didn't fail when installers were telling dispatch what they were going to do. ST didn't fail when a tech tried to walk away from a $20,000 job. What failed was management discipline — the muscle that says "we run today's work today, every day, in front of each other, with names on every red."

That muscle atrophies the same way every time: slowly, then all at once. Coaching gets pushed to "tomorrow." Hard conversations get pushed to "the right moment." Reds get marked green because nobody wants the meeting to end on a sour note. The numbers drift. Then one Tuesday a tech walks away from $20k and it takes six people and an email chain to figure out why.

UnifiedOps puts structural enforcement behind every part of that muscle:

  • Coaching has 15 minutes — from the moment the tech says he's done. Not "today." Fifteen minutes.
  • Happy call has 15 minutes. Same clock.
  • A job doesn't close because someone clicked "close." It closes when the work is actually done — coaching, happy call, escalation, complaint. The workflow IS the close mechanism.
  • Reds need a name and a same-day plan by 10 AM. Unowned reds escalate to the Owner automatically.
  • Markers can never be the same person as owners. Quiet reds become structurally impossible — not just culturally discouraged.
  • Every edit goes through approval. Adjustments are logged forever. There is no "fixing" the SLA timeline after the fact.

What we're building toward: a business that does $17M+ in electrical alone, runs on standard not on whether I'm in the building, and has a team that holds the line because the system makes the line impossible to ignore. That's the bridge. UnifiedOps is the planks.

This briefing exists so you can push back before the code is written. Read it. Find what's wrong. Tell me. The discipline of the 21 by 10 starts with the people building the tool.

What we're building — at a glance
  • Web app (desktop + mobile) that runs the 21-by-10 every day with structural enforcement, alongside Service Titan — not replacing it.
  • 15-minute SLA from "tech done" to coached + happy-called. Both required. System-enforced, no manual close button.
  • 9 roles, each with their own queue; every metric on the 21 has an owner and a different person marking it.
  • ~6 of 21 metrics auto-compute today; ~5 more become auto post-ST integration; the rest are manual judgement marks.
  • AI layer rolls out in phases — surfaces quiet reds, coaching evasion, cherry-picking, manager procrastination, and other defects humans miss in real time.
  • Phases 1-5 already built and running. Pre-build review is for Phases A0–E (foundation + workflow + 21×10 board + Hot Page + Active Work Board + real-time layer).
Core Operating Principle
Every customer- and tech-facing department is updating live, all day long.

Nobody waits for an end-of-day report. At any moment of the working day, every role can see exactly where they are tracking against every SLA — the 15-minute coaching window, the 15-minute happy-call window, the 10 AM 21×10 clearance, the per-metric daily pacing. The dispatcher board, CSR happy-call queue, manager coaching queue, controller daily-actuals view, tech personal dashboard, and 21×10 board all update in real time as data lands. Full stop. This is non-negotiable and shapes every screen.

What AI is NOT doing

  • Not making decisions for managers — surfaces patterns; humans act
  • Not auto-firing or auto-disciplining anyone
  • Not replacing human judgment on the 21 (markers still mark; AI flags suspicious marks)
  • Not generating performance reviews
  • Not exposed beyond Leadership — digest is Owner-only by default
  • Not reading customer PII or sensitive financial detail beyond what's already in the system
The premise: The 21×10 framework demands honesty by 10 AM. AI provides the audit layer that says "you marked it Green; let's check the underlying data." Quiet reds stop being culturally discouraged and start being structurally impossible.

03 — How the Build Will Actually Run

Multi-model cross-check at every step, zero marginal cost

This isn't a single-developer build. The owner runs a Mac Studio with 512 GB RAM hosting six local LLMs that work 24×7 with no API limits. That changes the math on quality assurance:

StepToolRole in the build
Architecture & scopingClaude (this Code session)Frontier model with full repo context. Owns design decisions, multi-file refactors, novel architecture.
Code writes (controllers, migrations, tests)Qwen3-Coder-Next via AiderSOTA open code model. Runs in terminal, edits files directly, applies the design.
Architecture review at end of each phaseDeepSeek-V3 (671B)Reads completed work, catches design drift, surfaces issues a coding model would miss.
Continuous test generationQwen3 30B (fast)Authors hundreds of test cases overnight against the new entities/endpoints. Coverage approaches 100% by default.
"Fresh eyes" feature reviewLlama 4 Maverick (244 GB)Different model family from Qwen/DeepSeek. Catches issues both miss by virtue of different training.
Embedding-based semantic code searchnomic-embed-textPowers fast "find the function that handles X" lookups for the other models.
Orchestration, disagreement resolution, verificationClaude (this session)When models disagree, the call comes back here. Verification before anything is considered done.

What this changes

  • Quality is the constraint, not effort. Dev hours are effectively free. We don't trade off scope for time; we trade off complexity for user experience.
  • Multi-model cross-check is the default, not a luxury. Every phase ends with at least two independent model reviews before the work is signed off.
  • Test coverage by default. Qwen3 30B grinds out tests in parallel with feature work. New phases ship with comprehensive coverage from day one.
  • Honest disagreements surface. When DeepSeek-V3 disagrees with Qwen3-Coder-Next, the human (Claude orchestrator) sees both arguments and adjudicates. Nothing gets approved by silent consensus.
  • No API cost ceiling. We can afford to over-review. Every PR-equivalent change gets read by 2-3 models.

What stays human

  • Architectural decisions when models disagree
  • Sign-off on each phase before the next begins
  • UX judgment calls (what the screen should feel like, not just whether it compiles)
  • Verification: "trust but verify" — the orchestrator confirms the work is actually done, not just claimed done
Competitive moat: Most teams ship code reviewed by one developer at best. This build ships code reviewed by 3-4 independent models plus a frontier orchestrator. The discipline of the 21×10 board has a parallel in the build process itself — nothing closes until every check is honest.

06 — Pacing Math (Quantitative Metrics)

How "green" gets computed

Inputs per metric, per division: monthly target value, direction (higher-is-better or lower-is-better), yellow buffer (default 5%), red buffer (default 10%).

Formula

WorkingDaysInMonth(D) = days in month(D) minus weekends and paid holidays WorkingDaysElapsed(D) = working days from month-start through D ExpectedDaily(D) = TargetValue / WorkingDaysInMonth(D) ExpectedMtd(D) = TargetValue × (WorkingDaysElapsed(D) / WorkingDaysInMonth(D)) ActualMtd(D) = sum of MetricDailyActual rows for division, metric, month ≤ D PacingRatio(D) = ActualMtd / ExpectedMtd Status (HigherIsBetter): ratio ≥ 1.00 → Green ratio ≥ 0.95 → Yellow ratio < 0.95 → Red Status (LowerIsBetter): ratio ≤ 1.00 → Green ratio ≤ 1.05 → Yellow ratio > 1.05 → Red

Worked example — Marketing Volume, MS Katy, May 2026

InputValue
Monthly target (calls)3,000
DirectionHigher is better
Working days in May 2026 (Mon–Fri minus 1 paid holiday)20
Working days elapsed through May 1913
Expected MTD = 3,000 × (13/20)1,950
Actual MTD entered by Owner1,830
Pacing ratio = 1,830 / 1,9500.938
StatusRED (below 0.95 threshold)

Marker (Controller) is now responsible for the Red. To clear it, they must add a named owner of the Red and a same-day plan. Until that happens, it's Unowned Red — auto-escalates to Owner at 10:01 AM local time.
